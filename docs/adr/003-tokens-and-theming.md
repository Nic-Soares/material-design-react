# ADR-003 — Material Design 3 tokens as the theming contract

## Status
Accepted (2026-11-03; roadmap `EP-03`). Revised the same day: color values
are generated with Material Color Utilities instead of copied.

## Context
The components come from a portfolio site where tokens grew with mixed names:
colors as `--md-sys-color-*`, typography as `--display-large-*`, elevation as
`--m3-elevation-*`, and state layers as about thirty precomputed variables per
theme (`--md-state-layers-light-on-surface-opacity-08`). The theme switched on
`body[data-theme="Light"]`. Precomputed state layers only match the colors they
were computed from: a consumer who changes the palette gets hover and press
states in the old colors. A library needs one naming scheme and a theme the
consumer controls.

The portfolio's color values were exported once from a theme tool and pasted
in: nothing records how they were made, and nothing can make them again for a
new source color, a dark scheme or a higher contrast. Google publishes the
algorithm behind the Material Design 3 color system as
[Material Color Utilities](https://github.com/material-foundation/material-color-utilities)
(`@material/material-color-utilities`, Apache-2.0): the HCT color space,
tonal palettes, the scheme variants, contrast levels and the 2025 (M3
Expressive) spec — the same code behind Android's dynamic color and Material
Theme Builder.

## Decision

### Names and theming
- Every token uses the Material Design 3 name as a CSS variable:
  `--md-sys-color-*`, `--md-sys-typescale-*`, `--md-sys-shape-*`,
  `--md-sys-elevation-*`, `--md-sys-state-*`, `--md-sys-motion-*`.
- Components read only these tokens, plus private variables of their own.
- State layers are computed with `color-mix()` from a color role and the M3
  state opacities, so they follow any palette.
- A consumer themes the library by setting the same variables. There is no
  JavaScript theme provider.

### Color values
- The default color tokens are generated by a script
  (`scripts/generate-color-tokens.ts`) with Material Color Utilities: the 2025
  spec, the Tonal Spot variant (the M3 default) and the M3 baseline source
  color `#6750A4`.
- The generated CSS is committed, so a color change shows up in review and
  Storybook and the tests need no extra step; CI regenerates it and fails if
  it differs.
- The tokens cover the color roles of the M3 spec. The palette key colors and
  the `*-dim` roles, which the 2025 spec uses only on watches, are left out.

### Schemes
- Light on `:root`; dark on `[data-theme="dark"]`, and under
  `prefers-color-scheme: dark` when no theme is set.
- Contrast: standard by default; medium on `[data-contrast="medium"]`; high on
  `[data-contrast="high"]`, and under `prefers-contrast: more` when no
  contrast is set. Each level exists in light and dark.

## Consequences
- Changing a color role changes every component, including its states.
- The token names are public API: renaming one is a breaking change.
- The defaults can be regenerated at any time, and every role in every scheme
  meets the contrast the spec requires for its level.
- Consumers can still set the values from any source; the runtime helper of
  [ADR-006](006-runtime-color-schemes.md) generates them from a source color.
